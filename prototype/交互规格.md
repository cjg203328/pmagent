# 三栏工作台交互规格

Status: draft
Owner: pmagent maintainers
Review cadence: 每个 UI 里程碑（M1.5 spike、M2 骨架、M5 定点改）
关联：[`../docs/product/PRD.md`](../docs/product/PRD.md) §4、§7；
[`../docs/product/交付物模板库.md`](../docs/product/交付物模板库.md)

对标对象：豆包工作 PC 端三栏工作台（左管任务 / 中显过程 / 右预览编辑）。
本文件把 PRD §7 的要求落成可实现、可验收的规格。

## 1. 信息架构

```text
Workspace（权限与知识边界，已有）
└── Project（projects 表）
    └── Job ★一等公民（包装 WorkflowRun）
        ├── trigger      manual | scheduled | from_message
        ├── inputs       附件快照 / 结构化参数 / 引用的知识规则
        ├── steps[]      WorkflowStepRun（复用）
        ├── artifacts[]  交付物（复用 artifacts/，归属改为 Job）
        ├── approvals[]  WorkflowApproval（复用）
        ├── thread[]     关联消息（对话降为通道）
        └── status       draft|queued|running|waiting|succeeded|failed|needs_input
```

**硬判据**：`Job` 必须能在无人对话时被创建、推进、完成（定时触发即可）。
做不到就不算「任务为中心」，只是给聊天加了个侧栏。

## 3. 各栏规格

### ① 任务栏

| 元素 | 规格 |
| --- | --- |
| 项目选择器 | 顶部下拉，切换后重置②③，不复用上一项目的 Job |
| 任务分组 | `进行中` / `计划中` / `已完成`，按 `Job.status` 映射 |
| Job 行 | 名称 + 状态徽标 + 进度条（完成 step 数 / 总 step 数）+ 相对时间 |
| 计划中 | 额外显示下次触发时间；点击展开历史 run 列表 |
| 会话 | **降为可折叠分组**，不与 Job 平级混排（当前实现的缺陷） |
| 空态 | 引导创建第一个 Job，附 3 个示例提示语 |

### ② 过程栏

Step 五态与视觉：

| 状态 | 记号 | 说明 |
| --- | --- | --- |
| 待执行 | `○` 灰 | 未开始 |
| 进行中 | `▓▓` 进度条 | 来自 SSE 事件 |
| 完成 | `●` ✓ 绿 | 可展开看中间产物 |
| 失败 | `✕` 红 | 展开错误码与重试入口 |
| 等待输入 | `?` 琥珀 | 渲染澄清卡片，Job 转 `needs_input` |

澄清卡片：问题文本 + 2–4 个预置选项 + 自定义输入 + 「跳过此项」；答案写回
`Job.inputs` 并从中断处续跑，**不重跑已完成 step**。

审批请求（写入型工具、外发、删除）沿用既有宿主审批边界，在②栏内联呈现，
不因 UI 改版放宽。

### ③ 成果栏

| 元素 | 规格 |
| --- | --- |
| 成果卡 | 文件名 + 大小 + SHA-256 状态 + 版本 + 生成时间 |
| 预览 | XLSX 表格视图 / DOCX 分页视图 / PDF 页图 / PPTX 缩略图 |
| 下载 | **仅 `verification.status=passed` 可下载**（沿用现有核验契约） |
| 版本 | 追加式，可切换查看历史版本，不可覆盖 |
| 定点改 | 选中表格区域或段落 → 输入修改意见 → 只重跑对应 step |
| 空态 | 「本任务尚未产出文件」+ 最近一次失败原因 |

## 4. 关键流程

### F1 新建任务（手动）

```
①[＋新建] → 弹窗选类型(S0/S1/S2/S3) → 拖入附件 → 确认参数 → Job=queued
→ ②栏出现 step 列表 → 逐步推进 → 产物落③栏
```

### F2 从对话升级为任务

```
②栏输入业务请求 → 命中技能 → ②栏出现「另存为任务」按钮
→ 点击后创建 Job，当前上下文成为 inputs，thread 关联
```

### F3 定时任务

```
①计划中 → 新建计划 → 选流程模板 + cron + 收件人 → job_schedules 落库
→ outbox_worker 租约领取 → 产出 Job → 结果按 §7 通知
```

复用 `evolution/scheduler.py:156 run_if_due()` 与 `memory/outbox_worker.py`
的租约/指数退避/死信骨架，不新写调度器。

### F4 定点改

```
③选中区域 → 输入「把这列改成万元」→ 定位产出该区域的 step
→ 只重跑该 step 及其下游 → 产物版本 +1 → 附件解析快照复用（计数不增加）
```

判据：F4 执行后，`harness.attachments.parse` 计数不变。

## 5. 状态与恢复

| 场景 | 行为 |
| --- | --- |
| 刷新页面 | 以 `run_id` + 最后 SSE id 续订，不重跑回合 |
| 断线 | 显示「连接中断，正在恢复」，恢复后补齐事件；缺口用 snapshot 兜底 |
| 长任务 | ②栏保持可见，允许切到别的 Job；后台继续推进 |
| 失败 | 保留已完成 step 与中间产物，提供「从失败处重试」而非「全部重来」 |
| 并发 | 本期单用户，不做乐观锁；同 Job 二次触发进入排队而非并行（PRD §12.2） |

## 6. 视觉令牌

**前置任务**：`ui/style_tokens.py` 目前只是用正则从 `ui_style.py` 的 2,691 行
`STYLE_CSS` 里读 `--pm-*`，**不是令牌源**。三栏改版前必须把它变成真正的单一来源，
否则同一处样式要同时改两个文件。

改版后新增令牌（命名沿用 `--pm-` 前缀）：

```text
--pm-col-task-rail      260px
--pm-col-process        minmax(0, 1fr)
--pm-col-artifact       420px
--pm-step-idle / -running / -done / -failed / -waiting
--pm-card-clarify-bg
--pm-artifact-verified / -pending
```

不得在页面级新增硬编码颜色（沿用 `OPTIMIZATION_STRATEGY.md` §1 的约束）。

## 9. 实现风险（必须先验证）

Streamlit 的 `st.columns` 不支持独立滚动与固定右栏。M1.5 spike 三选一：

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| A 组件级方案（自定义 component） | 保留现有 Streamlit 主链 | 组件内状态与 session_state 双向同步复杂 |
| B iframe 嵌预览 | ③栏实现最快 | 预览能力受限于可 iframe 的格式 |
| C ③栏独立页 + 深链 | 工程最简单 | 不是真「同屏」，违背 L2 体验 |
| D 脱离 Streamlit（`project/frontend/`） | 上限最高 | 全量前端重写，PRD §12.3 决策项 |

**若全部失败，不得降级为「交付物内联聊天」**——那等于回到现状。宁可推迟 M2。
