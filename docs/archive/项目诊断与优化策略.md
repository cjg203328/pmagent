## 三、核心问题（均带证据）

### 问题 1：测试套件存在但组织与 CI 衔接有短板（需修正的误判）
> 校正说明：初版诊断误以为 `tests/` 为空（因在 `artpm_agent/` 子目录内查找）。实际**根目录 `tests/` 已有一套完整测试**（18 个文件 + `conftest.py`，conftest 会 mock 掉外部 LLM 并改用临时库），覆盖 agent OCR、profiles、artifacts、conversation_store、workflows、risk_policy、streamlit 界面、回归等。此前报告的"48 passed"大概率来自这套套件。
- 真实短板：**`artpm_agent/` 根目录仍散落 7 个旧的 MCP 连通性测试**（`test_basic/mcp/mcp_enhanced/mcp_simple/agent_mcp/real_mcp*.py` + `quick_verify.py`），与 `tests/` 套件并存，造成目录混乱与重复认知。
- CI 配置用 **Python 3.10**，而本地运行环境是 **3.13**，存在版本漂移，可能导致 CI 绿但本地行为不一致。
- 没有**强制覆盖率门禁**，测试是否真正覆盖核心逻辑（skills 的 `execute`、意图路由、数据库 CRUD）缺乏量化约束。
- 散落的 MCP 测试需要本地起服务/网络，CI 中可能因无 server 而失败或悬挂，需加 skip 守卫。

### 问题 2：大量生产未用的死代码
- 旧入口：`app_old.py`(479)、`app_backup.py`(212)、`app_simple.py`(212) —— 与 `app.py` 功能重叠，**约 900 行**。
- 实验性 core（README 已声明"当前应用不导入"但仍留在仓库）：`core/chat_agent.py`、`core/llm_client.py`、`core/rag_system.py`、`core/tools.py`、`core/skills.py` —— **约 1,700+ 行**。
- MCP 客户端三版并存：`core/mcp_client.py` 仅被 `test_mcp.py` 引用、`core/mcp_client_real.py` 仅被 `test_real_mcp.py` 引用；**生产真正只用到 `core/mcp_client_enhanced.py`**。

### 问题 3：包结构缺失
- 无 `pyproject.toml`/`setup.py`，项目**不可作为规范包安装**，靠 14 处 `sys.path.insert(0, ...)` 硬加路径（含 `app.py`、`health_check.py`、`parsers`、`skills`、`utils` 等）。
- 嵌套包 `artpm_agent/artpm_agent/` 里只有一个空 `utils/__init__.py`，结构自相矛盾。
- 直接后果：新人上手难、CI 部署脆弱、导入随时可能因路径问题崩溃。

### 问题 4：巨型 `app.py`
- 单文件 3,528 行，含 **42 处 `except Exception`** 宽异常。任何 UI 改动都缺乏回归保护，且单文件难以并行开发。

### 问题 5：数据库无迁移机制
- `database/models.py` 用 SQLAlchemy 1.x 风格（`Column(...)`/`declarative_base`），未用 2.0 的 `Mapped`/`mapped_column`。
- 无 Alembic；自建 `_validate_existing_schema` 在列不匹配时直接 `raise RuntimeError`，**schema 一变就得手动重建库，有数据丢失风险**。

### 问题 6：重复实现
- **两套 LLM 客户端**：`core/llm_client.py`(387 行) 与 `utils/llm_client.py`(328 行) 职责重叠。
- **三套 MCP 客户端**（见问题 2）。

### 问题 7：可选能力未真正落地
- `requirements.txt` 中 `paddleocr`/`paddlepaddle`/`faiss-cpu` 全被注释；OCR、FAISS 向量检索始终处于"降级"状态，从未真正安装验证。

### 问题 8：CI 已写但未激活
- `.github/workflows/ci.yml` 写了 test/lint/type/security/build，但仓库**不是 git 仓库** → 无任何 push/PR 能触发它，等于没接入。

## 四、优化与完善开发策略（分阶段路线图）

> 原则：**先止血（地基+测试），再瘦身（死代码+解耦），后现代化（数据层），最后产品化与智能化**。每阶段的投入产出比已标注。

### 阶段 0 — 工程化地基（P0，约 2–3 天）
**目标**：让项目"可安装、可触发、可收集测试"。
- 新增 `pyproject.toml`，声明 `artpm_agent` 为包，删除全部 `sys.path.insert`。
- 修正 `pytest.ini`：`testpaths = tests`，把根目录 7 个测试移入 `tests/`。
- 初始化 git 仓库并连接 remote，让已有 CI 真正触发。
- 统一 Python 版本（CI 用 3.13，对齐本地托管运行时）。

### 阶段 1 — 测试护栏 + CI 真正跑起来（P0，约 3–5 天）
**目标**：让已有套件在 CI 稳定绿、覆盖率可量化。
- 先核实根目录 `tests/` 18 个测试在当前依赖下能否全部收集并通过（本地与 CI 对齐 Python 3.13）。
- 把 `artpm_agent/` 根散落的 7 个旧 MCP 冒烟测试并入 `tests/`（或加 skip 守卫），消除目录混乱。
- 为依赖本地 MCP server / 网络 / 密钥的测试加 `@pytest.mark.skipif` 守卫，避免 CI 悬挂或假红。
- CI 增加覆盖率门禁（如 `< 50%` 失败）；统一 Python 到 3.13；`mypy` 去掉 `continue-on-error` 逐步收紧。

### 阶段 2 — 死代码清理与架构解耦（P1，约 4–6 天）
**目标**：减包袱、降耦合。
- 删除 `app_old.py`/`app_backup.py`/`app_simple.py` 及未用的 `core/chat_agent|llm_client|rag_system|tools|skills.py`、`core/mcp_client.py`、`core/mcp_client_real.py`（约 2,600 行死代码）。
- **统一 LLM 客户端**为单一实现；MCP 只保留 `mcp_client_enhanced`。
- 拆分 `app.py`：按"对话/概览/项目/Excel 上传/设置"拆成 `pages/` 模块，每页 ≤ 400 行。
- 把 `except Exception` 收敛为领域异常（`SkillExecutionError` 等），保留错误上下文。

### 阶段 3 — 数据层现代化（P1，约 3–4 天）
**目标**：schema 可演进、数据可安全迁移。
- 引入 **Alembic**，首次迁移从当前 schema 生成基线；后续变更走版本化迁移。
- 模型逐步迁移到 SQLAlchemy 2.0 风格（`Mapped`/`mapped_column`）。
- 增加 `data/backup` 自动/手动备份脚本与说明。

### 阶段 4 — 能力完善与产品化（P2，约 6–10 天）
**目标**：把"可用 demo"变成"可交付产品"。
- 把 OCR/FAISS 做成真正可装的 `extra`（如 `pip install artpm-agent[ocr,vector]`），并在无依赖时明确降级。
- **报价单确认流**：上传解析后增加"人工确认 → 保存为项目"，避免解析结果直接污染业务库（此前报告已列为后续策略）。
- 增加轻量鉴权/多用户隔离（至少支持访问口令或反向代理鉴权），避免 `127.0.0.1` 之外暴露。
- 结构化日志脱敏（API Key、企业微信 Secret 不落盘）。

### 阶段 5 — 智能化与评估体系（P2，约 4–6 天）
**目标**：让"Agent 能力"可度量、可迭代。
- 建立 **Agent 评估集**：用固定用例校验意图路由准确率、各 Skill 输出正确性，作为回归基线。
- 离线检索增强：用真实 FAISS 替代确定性哈希向量（装了 extra 时），并做检索质量评估。
- 内置性能/成本监控面板（Skill 耗时、Token 预算消耗），呼应 `QUICK_WINS.md` 的监控接入。

## 六、立即可执行的 5 个快赢（按性价比排序）

1. **合并散落测试**（~30 分钟）：把 `artpm_agent/` 根 7 个旧 MCP 测试移入根 `tests/`，修正 `sys.path`，删除 `test_real_mcp.py`（测已删死客户端），让测试只在一处。
2. **删 3 个旧 app 入口**（~10 分钟）：`app_old/backup/simple`，减 ~900 行死代码，消除混淆。
3. **删 2 个死 MCP 客户端**（~10 分钟）：`core/mcp_client.py`、`core/mcp_client_real.py`，生产从未引用。
4. **初始化 git 并连 remote**（~20 分钟）：让已写好的 CI 真正跑起来，第一次获得自动化门禁。
5. **拆分依赖为可选 extra**（~1 小时）：`pip install artpm-agent[ocr,vector]`，让 OCR/FAISS 从"永远降级"变成"可选增强"。
