## 4. S-4 存储合并（11 个 SQLite）

**执行状态：前置调查完成，合并未执行（2026-09-20）。实测与本节假设存在三处分歧，

当前：`artpm`、`conversations`、`memory`、`episodes`、`feedback`、`strategies`、
`reflection`、`meta_memory`、`consolidation`、`telemetry` + `vector_store/`。

**本期只合并空库**：`feedback`、`strategies`、`memory` 实测 0 行业务数据。

1. 确认目标库确实为空（逐表 `count(*)`）。
2. 把对应 store 的默认路径改指 `conversations.db`，保留配置项可覆盖。

   PRD §5「冻结」的自我进化族，本期不动，只做「不再新增库」的约束。

风险：中。跨库无法 JOIN，合并会改变事务边界——`conversation_store` 与
`session_store` 的分离是有意设计（见 `STORAGE_CONTRACT.md`），**不得合并这两个**。

### 实测分歧（执行前必须澄清）

**分歧 1：`memory.db` 装的是业务表，不是记忆表。**

```text
memory.db 表：projects, tasks, task_assignments, staff, quotes,
             progress_updates, reminders, documents, operation_logs
```

这些表名与 `artpm.db` 高度重叠，与 `conversations.db` 的知识/会话/工作流表
**完全不同**。把它并入 `conversations.db`，会得到第三套 `projects` / `tasks`
表；跨库虽无法 JOIN，但同库重名表一旦被误用，后果比跨库更隐蔽。
手册称其为「记忆库」，实测它不是。

**分歧 2：`strategies` 属于手册自己要求冻结的族。**

`strategies.db` 的实现是 `artpm_agent/evolution/strategy_store.py`，即 PRD §5
「冻结」的自我进化族。手册第 4 条明确要求该族本期不动，却又在第 1 条把它列入
本期合并对象。两条要求互斥。

**分歧 3：三个库的路径都不是配置项。**

```text
feedback   → memory/feedback_store.py: default_feedback_db_path() → resolve_state_path()
strategies → evolution/strategy_store.py: default_strategies_db_path() → resolve_state_path()
memory     → config_data/default_config.json:90 "memory_db_path"
```

前两个由 `resolve_state_path(文件名, 环境变量名)` 硬编码决定，**没有配置键**。
手册要求「保留配置项可覆盖」，实测不存在这样的配置项——照做需要先新增配置项，
那已不是「合并空库」而是新增功能。

**未分歧的部分**：三库确实都是 0 行（`feedback` 0/2 表、`strategies` 0/2 表、
`memory` 0/10 表），前置条件成立。
