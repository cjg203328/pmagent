# 对话页面模型选择功能使用指南

## 功能概述

现在你可以在对话页面直接切换模型，无需去设置页面修改配置。这对于以下场景特别有用：

- **快速测试不同模型**：对比不同模型的回答质量
- **临时使用备用模型**：主模型繁忙时快速切换
- **按场景选择模型**：对话用小模型，分析用大模型

## 使用方法

### 1. 对话页面模型选择器

在对话页面右上角（对话标题右侧），你会看到一个模型选择下拉框：

```
┌─────────────────────────────────────────────────┐
│ ArtPM 助手        🤖 gpt-4o-mini [OpenAI] ▼    │
└─────────────────────────────────────────────────┘
```

点击下拉框，选择要使用的模型：

- ✅ 选择后立即生效（下一条消息使用新模型）
- ⚠️ 临时切换，不会保存到设置（关闭应用后恢复默认）
- 💡 切换时会显示 toast 提示确认

### 2. 可用模型列表

模型列表来自两个来源：

**方式 A：从设置页「同步模型」（推荐）**

1. 进入设置页
2. 配置 API Key 和 API Base URL
3. 点击「同步模型」按钮
4. 系统自动获取该 API 站点支持的模型列表

**方式 B：手动配置 `.env`**

```env
LLM_AVAILABLE_MODELS='["gpt-4o", "gpt-4o-mini", "gpt-3.5-turbo"]'
```

**重要提示：**
- 只保留与主模型相同 provider 的候选
- 避免跨 provider 切换导致认证失败
- 参见 [FIXED_MODEL_FALLBACK_ISSUE.md](../reports/FIXED_MODEL_FALLBACK_ISSUE.md)

### 3. 模型显示格式

模型选择器会自动格式化模型名称，让它更易读：

| 原始 ID | 显示名称 |
|--------|---------|
| `gpt-4o-mini` | `gpt-4o-mini [OpenAI]` |
| `claude-3-5-sonnet-20241022` | `claude-3-5-sonnet [Anthropic]` |
| `glm-5.2` | `glm-5.2 [Zhipu]` |
| `deepseek-v4-flash` | `deepseek-v4-flash [DeepSeek]` |

版本日期后缀（如 `-20241022`）会自动移除，保持界面简洁。

## 友好错误提示

当模型调用失败时，系统会提供详细的错误说明和解决建议：

### 认证失败

```
❌ 模型 gpt-4o-mini 认证失败。

**可能原因：**
- API Key 无效或已过期
- API Base URL 配置错误
- 该模型不可用于当前账户

**解决方案：**
1. 检查设置页的 API Key 和 API Base URL
2. 确认 API Key 对应的服务支持该模型
3. 尝试切换到其他模型（对话页右上角选择器）

💡 你可以尝试切换到其他模型：gpt-4o、gpt-3.5-turbo
```

### 超时

```
⏱️ 模型 gpt-4o 响应超时。

**可能原因：**
- 网络不稳定或 API 服务繁忙
- 该模型响应速度较慢

**解决方案：**
1. 点击「重新生成」按钮重试
2. 尝试切换到响应更快的模型
3. 检查网络连接和 API Base URL
```

### 服务繁忙

```
🚦 模型 gpt-4o-mini 当前服务繁忙。

**可能原因：**
- API 速率限制（请求过于频繁）
- 服务负载过高
- 账户配额不足

**解决方案：**
1. 稍等片刻后重试
2. 切换到其他可用模型
3. 检查账户配额和使用限制
```

### 连接失败

```
🔌 模型 gpt-4o-mini 连接失败。

**可能原因：**
- API Base URL 错误或无法访问
- 网络连接问题
- API 服务暂时不可用

**解决方案：**
1. 检查设置页的 API Base URL 是否正确
2. 确认网络连接正常
3. 尝试访问 API Base URL（浏览器测试）
4. 切换到其他可用模型
```

### 模型不存在

```
❓ 模型 unknown-model 不存在或不支持。

**可能原因：**
- 模型 ID 拼写错误
- 该 API 服务不提供此模型
- 模型已下线或更名

**解决方案：**
1. 点击「同步模型」按钮获取可用模型列表
2. 切换到其他可用模型
3. 检查 API 文档确认模型 ID
```

## 最佳实践

### 1. 按场景选择模型

不同模型有不同的强项：

| 场景 | 推荐模型 | 原因 |
|-----|---------|------|
| 日常对话 | `gpt-3.5-turbo`, `gpt-4o-mini` | 响应快，成本低 |
| 复杂分析 | `gpt-4o`, `claude-3-5-sonnet` | 推理能力强 |
| 代码生成 | `gpt-4o`, `deepseek-coder` | 代码质量高 |
| 多模态 | `gpt-4o`, `gemini-pro-vision` | 支持图片 |

### 2. 验证可用模型

启动应用前，运行配置检查工具：

```bash
python -m artpm_agent.tools.check_config
```

确认：
- ✅ API Key 有效（不是占位符）
- ✅ 候选模型列表不跨 provider
- ✅ 数据路径可访问

### 3. 同步模型列表

定期在设置页点击「同步模型」，获取最新的可用模型：

- **推荐频率**：每周一次或 API 服务更新后
- **作用**：确保模型列表与 API 站点保持一致
- **注意**：同步后需要保存设置才能生效

### 4. 切换模型的时机

在以下情况考虑切换模型：

- ❌ 当前模型连续失败 2 次以上
- ⏱️ 当前模型响应明显变慢
- 🎯 任务需要特定模型的能力（如视觉理解）
- 💰 想要降低成本（切换到更便宜的模型）

## 技术细节

### 模型覆盖机制

用户选择的模型会临时覆盖 `ModelGateway` 的主模型 ID：

```python
# 原始配置（来自 .env）
LLM_MODEL=gpt-4o-mini

# 用户在对话页选择了 gpt-4o
# → ModelGateway._llm_config["model"] 临时覆盖为 gpt-4o

# 关闭应用或刷新页面后
# → 恢复为 gpt-4o-mini
```

### 会话生命周期

- **临时切换**：只在当前 Streamlit 会话生效
- **不持久化**：不会修改 `.env` 或数据库
- **自动恢复**：重启应用后恢复默认模型

### Failover 行为

即使用户手动切换了模型，failover 机制仍然生效：

```
用户选择: gpt-4o
    ↓
gpt-4o 失败（超时/繁忙）
    ↓
自动切换到候选: gpt-4o-mini
    ↓
成功 ✅
```

## 常见问题

### Q: 切换模型后立即生效吗？

A: 是的。下一条消息会使用新模型。如果需要用新模型重新回答当前问题，点击「重新生成」按钮。

### Q: 切换后会保存到设置吗？

A: 不会。这是临时切换，不会修改 `.env` 文件。如果想永久切换，请去设置页修改并保存。

### Q: 为什么有些模型显示但选择后失败？

A: 可能原因：
- 模型列表过期（点击「同步模型」更新）
- API Key 对应的账户没有该模型权限
- 模型已下线或更名

### Q: 可以跨 provider 切换吗（OpenAI → Anthropic）？

A: 技术上可以，但不推荐。不同 provider 需要不同的 API Key，跨 provider 切换可能导致认证失败。建议在设置页完整配置后再切换。

### Q: 如何查看当前使用的模型？

A: 对话页右上角的模型选择器会显示当前模型。也可以在设置页查看「最近使用的模型」。
